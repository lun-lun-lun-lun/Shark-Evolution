# Keep SMASH's Toolchain, Replace Its Netcode

Almost everything SMASH got right about tooling carries over to Shark Evolution, and almost nothing about its runtime netcode should. As of October 30, 2026, Rokit, Rojo, Wally, Lune, Blink, jecs, Planck, vide, strict Luau and the `src/shared|server|client` layout are still sound. They need only patch upgrades: Rojo 7.7.1, Lune 0.11.1, rodeo 1.5.1, Blink 0.18.9, jecs 0.11.0, vide 0.4.1 and TopbarPlus 3.5.0. Three things should go: the archived Aftman fallback, Lyra (replace with ProfileStore 1.0.3) and crunchyroll (replace with Roblox's Animator and Animation Graphs). The decisive change is architectural. Drop the 60 Hz prediction/reconciliation loop, the custom codec generator and the acknowledged delta snapshots that left SMASH at a ~41 ms p95 server frame. Instead, each phone owns its own shark's physics, and the server owns only the truth about who ate what, checked by rewinding target positions within a capped window. Hundreds of fish live on the server as compact data — closed-form school paths, plus a 10–20 Hz tier for fish reacting to sharks — and stream as ~10-byte quantized records to clients that draw them as pooled, instanced, anchored meshes. Roblox's native Server Authority, generally available since July 9, 2026, fits a swimming shark on paper. Two problems rule it out today for 10–20 players on 150–300 ms mobile links: an open report of input delay that grows with player count at 100+ ms ping, and client resimulation that staff put at ~6.25× normal load at 100 ms. On the client, four choices set rendering and memory budgets that 2–3 GB phones can meet: fog that caps the view at ~200 studs, StreamingEnabled on, Soft lighting instead of Future plus Bloom, and no Terrain water. Adopt the stable 2026 additions — the Input Action System, Animation Graphs, Jest Roblox with Open Cloud Luau Execution, and Studio's Network Simulator. Finally, publish under a distinct title, because "Shark Evolution" sits close to Ubisoft's trademarked Hungry Shark Evolution.

## Fish live on the server as data and on phones as pixels

SMASH's netcode targeted the hardest case in multiplayer games: 40 fighters whose every hit depends on precise predicted positions. It still missed its 12 ms server target. Shark Evolution's hard case is different. It has hundreds of entities whose exact positions matter only at the moment a shark bites, and letting the engine replicate them is the expensive option. Humanoid NPCs moved with `MoveTo` cost about **110 KB/s at 200 NPCs and 160 KB/s at 500** ([DevForum](https://devforum.roblox.com/t/performance-tips-network-bandwidth-client-framerate-etc-for-custom-npc-replication/4202236)). Moving 2,000 server-side MeshParts sent roughly **2,500 KB/s** to clients ([DevForum](https://devforum.roblox.com/t/the-definitive-tutorial-to-game-optimization-everything-you-need-to-know/4629258)).

Between 2021 and 2026 the community converged on the opposite pattern: the server keeps NPCs as plain data with no Instances, and clients own, pool and interpolate every model. Astro Force cut 100 moving units from 35 KB/s to 10 KB/s with 10 Hz updates and 16-bit positions ([DevForum](https://devforum.roblox.com/t/how-we-reduced-bandwidth-usage-by-60x-in-astro-force-roblox-rts/1202300)). A stress test held **10,000 NPCs at 55–60 FPS on an iPhone 8 Plus**, and a later version packed positions into 29 bits for an estimated 17.7 KB/s per 1,000 NPCs ([DevForum](https://devforum.roblox.com/t/10000-physical-npcs-running-with-60-fps-on-low-end-device/3660293)). An RTS runs 800+ data-only units with updates about every 10 frames ([DevForum](https://devforum.roblox.com/t/how-we-are-developing-an-rts-game-with-good-performance-for-more-than-200-units/3281168)). These benchmarks are self-reported on mixed hardware, but they agree in direction and magnitude.

### Three fish tiers make server cost scale with schools, not fish

The cheapest fish is one the server never steps. Most prey should live in calm schools whose positions are a closed-form function of time: a school anchor follows a looping path, and each fish adds an offset computed from a hash of the school seed and its index. The server evaluates a fish only to validate a bite, aim a predator or decide relevancy. Clients evaluate the same function against `workspace:GetServerTimeNow()`, the trick tower-defense games use for path-following enemies ([DevForum](https://devforum.roblox.com/t/2413006)).

Closed form is chosen over stepped "deterministic flocking" on purpose. Roblox's `Random` docs promise no identical sequence across platforms or engine versions ([Roblox docs](https://create.roblox.com/docs/reference/engine/datatypes/Random)). Floating-point results are notoriously hard to make identical across compilers and instruction sets ([Gaffer On Games](https://gafferongames.com/post/deterministic_lockstep/)). Stepped boids are chaotic, so tiny differences between x86 servers and ARM phones compound, whereas a function evaluated fresh from *t* produces errors that never accumulate. For the same reason, per-fish randomness should come from `bit32` integer hashes rather than `Random` streams.

A scatter becomes a reliable event (school id, start time, origin, seed) that server and clients evaluate as the same closed-form burst. Only fish actually being chased are promoted to individual simulation. The visual jump at promotion is hidden by an error offset that decays each frame, as Gaffer recommends ([Gaffer On Games](https://gafferongames.com/post/state_synchronization/)). Where full flocking (boids) is wanted, run it only on that small active set and cap each fish at six or seven neighbours, the topological rule real starling flocks follow ([Ballerini et al.](https://arxiv.org/abs/0709.1916)). The byte and rate figures in the table are design targets derived from the precedents above, not measurements.

| Tier | Which fish | Server state | Network traffic | Client rendering |
|---|---|---|---|---|
| A: calm schools | Most prey | One record per school: id, species, seed, spawn time, path parameters, alive bitmask | ~20–40 B once when the school becomes relevant, then reliable events (scatter, eaten) | Evaluate the path at estimated server time, with no interpolation buffer |
| B: reacting fish | Fleeing, chased or large prey | Preallocated slots in parallel arrays, stepped at ~10 Hz | ~10 B records, 10–20 Hz near a shark and 2–5 Hz farther out, unreliable and sequence-numbered | Interpolate with a 150–350 ms buffer |
| C: AI predators | A handful to ~20 | jecs entities deciding at 2–5 Hz and steering at 10–20 Hz | Same stream as tier B at the near rate | Interpolated, animated models |

### One 10-byte record replaces the codec generator and acknowledged deltas

Interest management decides what each phone hears, and it has three parts. The first is a uniform grid of 128–256-stud cells. The second is a per-player interest radius matched to the fog (~200 studs), with a 20–40-stud hysteresis band of the kind community developers use to stop edge flicker ([DevForum](https://devforum.roblox.com/t/performance-tips-network-bandwidth-client-framerate-etc-for-custom-npc-replication/4202236)). The third is Gaffer's priority accumulator: every object gains priority each tick, packets fill in priority order up to a byte budget, and leftovers go first next time ([Gaffer On Games](https://gafferongames.com/post/state_synchronization/)). Together they reproduce in miniature what Unreal's Replication Graph does for Fortnite's ~50,000 replicated actors ([Unreal docs](https://dev.epicgames.com/documentation/en-us/unreal-engine/replication-graph-in-unreal-engine)).

A tier-B record needs only a u16 id, three u16 coordinates (1/8-stud steps across an 8,192-stud ocean) and two u8 angles: **about 10 bytes**. At 10 Hz, 100 nearby fish cost ~10 KB/s per player before engine compression, and one packet carries ~90 fish. That is comfortably inside SMASH's ~32 KiB/s per-client ceiling, which remains a sensible monitored target. Packets must fit the UnreliableRemoteEvent payload cap, which Roblox raised from 900 to **1,000 bytes on March 12, 2025** ([DevForum](https://devforum.roblox.com/t/introducing-unreliableremoteevents/2724155)), so SMASH's 880-byte packets were sized for the old limit. The engine compresses buffers before applying the cap, which makes the effective size unpredictable; ~950 B is a safe ceiling ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/UnreliableRemoteEvent)). Throttled unreliable messages are dropped rather than delayed and arrive unordered, so every packet carries a sequence number and stale ones are discarded ([Roblox docs](https://create.roblox.com/docs/scripting/events/remote)). Encode each grid cell once per tick and build each player's packet by copying in the cells it needs. Per-player re-encoding is exactly the kind of server work SMASH could not afford.

SMASH's two most complex mechanisms buy little here. Acknowledged delta snapshots shine when most state is static. Gaffer's demo spends one bit per unchanged object against a baseline about one round trip old ([Gaffer On Games](https://gafferongames.com/post/snapshot_compression/)), but swimming fish change every tick, and on 300 ms links the baseline is stale anyway. A 60 Hz rate is just as unnecessary when interpolation hides lower rates. Buffering three send intervals survives two consecutive losses, which gives ~300–350 ms of delay at 10 Hz and ~150 ms at 30 Hz, and Hermite interpolation removes the artifacts that linear interpolation shows at 10 Hz ([Gaffer On Games](https://gafferongames.com/post/snapshot_interpolation/)). The folkloric 50 KB/s ceiling, meanwhile, was the legacy physics sender's throttle; a Roblox engineer says NextGenerationReplication shares a "much higher" limit ([DevForum](https://devforum.roblox.com/t/4728153)). On weak cellular links the real constraint is the link itself. It shows up as data ping climbing above network ping while replication queues fill ([Roblox docs](https://create.roblox.com/docs/performance-optimization/identify)).

Blink remains the right interface-definition (IDL) compiler for typed, low-rate events such as bites, eats, spawns and growth. **0.18.9 (September 19, 2026) is a required upgrade**, because it fixes NaN scalars and vectors slipping past range validation, which SMASH's 0.18.8 still accepts ([Blink releases](https://github.com/1Axen/blink/releases)). Its open issue #45 lets a client crash a server with an oversized buffer, and the maintainer has deferred the fix to the 1.0 rewrite ([GitHub](https://github.com/1Axen/blink/issues/45)). Zap has the same class of bug as #219 ([GitHub](https://github.com/red-blox/zap/issues/219)), and the dormant ByteNet has it as #34 ([GitHub](https://github.com/ffrostfall/ByteNet/issues/34)), so switching libraries buys no safety. The fix is a byte-length check and a per-player rate check wrapped around Blink's listeners, run before decoding.

Bandwidth will not separate the candidates either: Blink, Zap and ByteNet all land near 42 Kbps on the same workload in Blink's benchmark ([Blink benchmarks](https://github.com/1Axen/blink/blob/main/benchmark/Benchmarks.md)). Blink 0.18 also makes one remote call per unreliable fire instead of batching per frame ([Blink source](https://github.com/1Axen/blink/blob/main/src/Generator/init.luau)), another reason to ship fish state as one hand-written buffer per tick. Tellingly, Blink's 1.0 rewrite plans quantized numerals, boolean bit-packing and compile-time checks on unreliable packet size (#104, #105, #108) — the features SMASH's generator built by hand ([Blink issues](https://github.com/1Axen/blink/issues)). Wait for that release rather than rebuild the generator. BlinkBlox is a schema-compatible fork of Blink 0.18, announced September 27, 2026, with size caps checked before parsing, token-bucket rate limits, quantized floats and per-player outbound budgets ([DevForum](https://devforum.roblox.com/t/4898948)). It merits a time-boxed trial, but it is one month old and its benchmarks are self-reported.

### Flat arrays, time slicing and jecs 0.11 aim at SMASH's p95 problem

The server heartbeat is capped at 60 FPS, a 16.67 ms frame ([Roblox docs](https://create.roblox.com/docs/performance-optimization/identify)). No SMASH profile exists to show whether its 41 ms p95 came from steady 60 Hz per-entity work or from allocation bursts. Bursts are plausible: Luau's incremental garbage collector can pause for "tens of milliseconds" in atomic steps, and high allocation rates force extra collection work ([Luau](https://luau.org/performance)). The same measures address both causes. Run the fish simulation at 10–15 Hz, time-sliced across Heartbeat frames against a fixed budget; QuickZone's budgeted scheduler is a ready pattern that produces almost no garbage ([GitHub](https://github.com/LDGerrits/QuickZone)). Keep fish in preallocated arrays or buffers with free-lists, and mark numeric modules `--!native`, which Roblox recommends for math-heavy table and buffer code ([Roblox docs](https://create.roblox.com/docs/luau/native-code-gen)).

Even at a pessimistic assumed 5 µs per fish update, 600 actively simulated fish at 10 Hz average ~0.5 ms per frame. That makes two p95 targets realistic, pending MicroProfiler confirmation on live servers: ≤3 ms for simulation plus packet building, and ≤10 ms for the whole frame. Parallel Luau is a late lever. Users reported only about two worker threads on live servers before Roblox moved to player-count-based CPU allocation in November 2025, and the new formula is unpublished ([DevForum](https://devforum.roblox.com/t/worker-count-capped-at-3-in-game/3262835), [DevForum](https://devforum.roblox.com/t/launching-even-more-server-cpu/4044040)).

jecs remains the dominant Luau ECS, with 477 GitHub stars and no rival above 117 ([GitHub](https://github.com/Ukendio/jecs)). Move to **0.11.0**, whose one breaking change bans structural changes inside `on_remove` hooks. Main also holds a September 17, 2026 fix for worlds that repeatedly create and destroy archetypes ([jecs releases](https://github.com/Ukendio/jecs/releases), [jecs commits](https://github.com/Ukendio/jecs/commits/main)). Use jecs for varied entities — sharks, predators, pickups, evolutions — but not for the swarm. Hundreds of identical records with constantly changing state belong in a parallel-array module with integer state enums, which never triggers archetype moves on the hottest path. Planck can stay at 0.2.0, since its 0.3.0 has sat at release candidate 2 since May 10, 2026 ([Planck releases](https://github.com/YetAnotherClown/planck/releases)). replecs fits neither the swarm nor its constantly shifting relevancy: 0.3.x needs manual full-state sends whenever a player's filter changes, and 0.4.0 is an unreleased rewrite ([replecs releases](https://github.com/PepeElToro41/replecs/releases)).

## Client-owned sharks beat Server Authority on 300 ms mobile links

Movement authority decides how the game feels on a bus. Three models are available in late 2026, and they trade feel, cheat resistance and server cost differently.

| Model | Feel at 150–300 ms | Cheat resistance | Server cost | Status, Oct 2026 |
|---|---|---|---|---|
| Client network ownership with server checks | Instant, never corrected | Detects speed and teleport within a tolerance; eats validated on the server | Lowest; the server validates but never simulates players | Roblox default; stable |
| Native Server Authority | Instant while predictions match; corrected on contact, jitter and dropped inputs | Prevents speed, teleport, fly and fling | Higher on both ends; client resimulation grows with latency | Generally available July 9, 2026; open high-ping bugs |
| Custom predicted netcode (SMASH, Chickynoid) | Similar to Server Authority | Prevents | Highest; every edge case is yours | SMASH missed its budget; Chickynoid uses a box collider and was last updated May 2024 ([GitHub](https://github.com/easy-games/chickynoid)) |

### Server Authority fits on paper and fails the high-ping test

Server Authority deserves a fair hearing. It reached full release on July 9, 2026, and Roblox presents it as preventing fly, speed and fling cheats ([Roblox newsroom](https://about.roblox.com/newsroom/2026/07/creating-responsive-cheat-resistant-games-roblox-server-authority)). Every mover a shark needs is predicted under it — `VectorForce.Force`, `AlignOrientation.CFrame`, `AssemblyLinearVelocity` and every ControllerManager property — so a mover-driven swimmer is supported ([community reference](https://github.com/MrChickenRocket/Server-Authority-Tutorial-Cakeman/blob/main/docs/reference/server-authority.md), [Roblox docs](https://create.roblox.com/docs/reference/engine/classes/ControllerManager.md)).

Its problems land on this game's exact conditions. A July 29, 2026 report, reproduced by a second developer on August 18 with no fix reported, shows **input delay growing with each added player at ~100+ ms ping, until play becomes unplayable at about four players** ([DevForum](https://devforum.roblox.com/t/server-authority-input-delay-scales-with-player-count-at-high-ping/4763481)). Resimulation is the common case rather than the exception: one sample replayed 105 steps against 91 live ones ([community reference](https://github.com/MrChickenRocket/Server-Authority-Tutorial-Cakeman/blob/main/docs/reference/server-authority.md)). Staff put its client cost at **~6.25× a client-authoritative game at 100 ms**, growing with latency, and its fixes — input-latency injection and partial prediction — are still prototypes or stated directions. Staff also confirm that player collisions always mispredict and that no server-side rewind exists ([DevForum](https://devforum.roblox.com/t/server-authority-tech-deep-dive-engineering-insights/4624565)).

Testers report stutter above ~40 studs/s and endless mispredictions with VectorForce and constraints ([DevForum](https://devforum.roblox.com/t/server-authority-client-beta-was-a-damn-nightmare-heres-some-advice/4712758)), a zone that covers every boosting shark and every PvP bite. The release's known issues add a 64-attribute cap on synced custom state, and mobile builds that trail desktop and cannot connect until updated ([DevForum](https://devforum.roblox.com/t/full-release-ship-fair-and-competitive-games-with-server-authority/4727993)). Enabling Server Authority also forces NextGenerationReplication, Deferred signals, StreamingEnabled, fixed-step simulation and input through the Input Action System only. A Roblox engineer warns that NextGenerationReplication "does a lot of extra CPU work on the Server" and that "Server Performance with 20+ player games needs a lot of work" ([DevForum](https://devforum.roblox.com/t/4139321)). A 12-player shooter's receive bandwidth fell by nearly 100 KB/s when it turned Server Authority off ([DevForum](https://devforum.roblox.com/t/4728153)). Whether the July bug was fixed by October 30 is unknown, so treat it as a go/no-go test rather than an assumption.

Client ownership wins version 1 because nothing is ever rolled back: the local shark responds instantly, and the server spends nothing simulating it. Its weakness is real. A client that owns its shark can teleport, fly, set NaN velocities and fire Touched without contact ([Roblox docs](https://create.roblox.com/docs/scripting/security/network-ownership), [Roblox docs](https://create.roblox.com/docs/physics/network-ownership)). But in a mostly PvE eating game the cheat that matters is "eat everything fast," and server-validated eating closes it under any model. Around that core, the server should enforce a full-3D leaky-bucket speed budget (the XZ-plane projection Roblox suggests does not fit swimming), sanitize NaN and infinite velocities, and disable shark-to-shark collisions with collision groups to remove the main fling vectors. Violators should be pulled back rather than kicked, since Roblox warns that basic heuristics flag innocent players on unstable connections ([Roblox docs](https://create.roblox.com/docs/scripting/security/network-ownership)).

Keep the door open to Server Authority later. Write the swim step as a pure `step(state, input, dt)` function, read input through the Input Action System, build under Deferred signals with streaming on, and refer to entities in remote events by numeric ID. That last point matters because NextGenerationReplication drops the guarantee that property updates arrive before related remote events ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/Workspace)).

The swimmer itself pairs best with plain movers in a "dry" ocean with no Terrain water: LinearVelocity or VectorForce for thrust, AlignOrientation for heading, and an upward force of mass × `workspace.Gravity` to cancel gravity. ControllerManager with a SwimController is the neater alternative. It drives the root toward `MovingDirection × BaseMoveSpeed`, pitches toward `FacingDirection` and rolls to stay upright, with no Humanoid required ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/SwimController.md)). However, its BuoyancySensor recognizes only Terrain water ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/BuoyancySensor.md)), and nothing documents how SwimController behaves outside water or handles gravity, so a one-day prototype should settle it. Humanoid swimming is ruled out, because a freely pitching shark would fight the Humanoid state machine.

### Rewind caps sized to each fish tier keep bites fair

Bites need custom lag compensation under every model. The standard technique is server-side rewind: keep a short position history and check each claim against where the target was when the attacker saw it ([Gambetta](https://www.gabrielgambetta.com/lag-compensation.html)), with a cap that limits unfairness to the victim. Riot tunes that cap per region, and its playtests show the stakes: 10 ms of peeker's advantage swung duel win rates from ~90% for the defender to ~90% for the peeker ([Riot](https://www.riotgames.com/en/news/peeking-valorants-netcode)). Secondary guides put typical shooter caps at 200–300 ms ([guide](https://abratabia.com/multiplayer-web-games/lag-compensation.php)).

In this game the client detects a bite, plays the chomp, hides the fish optimistically and sends `{targetId, renderServerTime}` through a rate-limited Blink event. The server runs cheap checks first: the target is alive, the shark is large enough, the cooldown has elapsed, and an eats-per-second leaky bucket (which doubles as a growth-rate cap) has room, with the first valid claim winning. It then clamps the claimed time, evaluates the target at that time — in closed form for tier A, or from a 10–20 Hz position ring buffer for tiers B and C — and accepts if the target lies within bite range plus a tolerance and inside the mouth cone.

The tier design pays a second dividend here. A calm-school fish renders at server time, so the server need only rewind it by the client-to-server half of the round trip (~75–150 ms). An interpolated fish was drawn about one full round trip plus its buffer in the past — roughly 450–500 ms for a 300 ms player at 20 Hz. Clamp each such claim to that player's measured RTT plus the tier's buffer plus a margin, under a PvE ceiling near 500 ms. No human victim is wronged, and the per-player clamp stops low-ping players from claiming stale bites.

PvP deserves a tighter ~150–250 ms ceiling that favors the victim, plus a check that the victim is still near the attacker at server time. Beyond that ceiling, high-ping attackers must lead their target. Generous mouth radii and a short, telegraphed lunge will therefore do more for PvP fairness than a longer rewind, in line with Roblox's advice to hide latency with slower acceleration and delayed effects ([Roblox docs](https://create.roblox.com/docs/projects/server-authority/techniques)). Roblox does not document the interpolation delay it applies to replicated characters, so log the rewind amount, RTT and rejection reason for every bite and tune the caps on real mobile traffic.

### The Input Action System is the only future-proof input path

Input should flow through the Input Action System, generally available since June 11, 2026. It is the only input path Server Authority accepts, and Roblox's default PlayerScripts adopt it by default in early 2027 and require it by mid-2027 ([DevForum](https://devforum.roblox.com/t/full-release-input-action-system-ias-newly-converted-player-scripts/4678416)). Four actions cover the game: Move and Look as Direction2D actions, plus Boost and Bite as Bool actions, each bound to keyboard, gamepad and touch through `UIButton` ([Roblox docs](https://create.roblox.com/docs/input/input-action-system)).

Two gaps from the release thread need early prototypes. Four on-screen buttons reportedly cannot drive a Direction2D action, and a question about reading the default mobile thumbstick went unanswered, so a custom UserInputService touch joystick may be required. Auto-forward cruising with camera-relative steering keeps simultaneous touches to a minimum. Large Boost and Bite buttons belong in the right-thumb zone, with a `HapticEffect` pulse on every successful eat ([Roblox docs](https://create.roblox.com/docs/input/mobile)).

## A 200-stud fog bubble sets every client budget

Low-end phones fail on memory first and frame time second. Roblox staff state that "the overwhelming majority of crashes on mobile are memory-related" ([DevForum](https://devforum.roblox.com/t/psa-mobile-client-crash-reclassification-in-creator-hub/4053071)). A 2 GB phone reportedly leaves Roblox about 800 MB ([DevForum](https://devforum.roblox.com/t/streaming-enabled-can-run-over-memory-management-to-crash-client/3305729)), and Roblox's own example budget for a baseline device is under 1,000 draw calls and 1 million triangles ([Roblox docs](https://create.roblox.com/docs/performance-optimization/design)). Low-end devices can currently cut draw distance to **200 studs**, with a 500-stud minimum planned for late 2026 ([Roadmap](https://devforum.roblox.com/t/creator-roadmap-2026-fall-update/4880208)).

Capping underwater visibility with fog at roughly 120–200 studs therefore costs nothing artistically, since the deep ocean should be murky anyway. It makes every device look the same and shrinks every other budget: streaming radii, fish render radius, network interest radius and textures held in memory. The ocean should feel vast through depth-zone color shifts, near-camera "marine snow" particles and rare, huge, low-poly silhouettes looming through the murk — not through draw distance.

Turn **StreamingEnabled on**, the reverse of SMASH. Roblox calls streaming the highest-impact memory option ([Roblox docs](https://create.roblox.com/docs/performance-optimization/improve)), and both SLIM and Server Authority require it. Use Opportunistic stream-out, Improved model streaming, a StreamingTargetRadius of ~256–512 studs instead of the 1,024 default, and a StreamingMinRadius of 64–128 ([Roblox docs](https://create.roblox.com/docs/workspace/streaming)). Test the recommended PauseOutsideLoadedArea integrity mode with boosting sharks under the 3G network preset; Roblox's planned late-2026 adaptive radius and path pre-fetching should help ([Roadmap](https://devforum.roblox.com/t/creator-roadmap-2026-fall-update/4880208)). Instances created by client scripts never stream out ([Roblox docs](https://create.roblox.com/docs/workspace/streaming)), so the fish pool must cull itself by distance and camera view. SLIM can merge dense reef and wreck clusters into fewer draw calls and falls back harmlessly where unsupported. But it excludes animated and runtime-modified models, so it will not help fish or sharks, and no official post confirms it has left Client Beta on phones ([Roblox docs](https://create.roblox.com/docs/workspace/streaming/slim), [DevForum](https://devforum.roblox.com/t/client-beta-introducing-scalable-lightweight-interactive-models-slim/4034709)).

### Instanced, anchored, pooled fish cost tens of draw calls

The fish renderer lives or dies on instancing. Identical meshes share one draw call only when they also share the same SurfaceAppearance, texture or material ([Roblox docs](https://create.roblox.com/docs/performance-optimization/improve)). Each species should therefore be one MeshPart asset with a shared appearance varied by `Color` tint, which keeps 300 fish across ~10 species in the tens of draw calls (verify with Shift+F2). Skinned meshes appear not to instance: one developer's 1,000 rigs jumped from 300 to over 1,000 draw calls after switching to skinned single-part meshes ([DevForum](https://devforum.roblox.com/t/struggling-to-efficiently-move-1000-assemblies/4203225)). Reserve skinning for player sharks and the 20–30 nearest fish, writing one to three tail-bone transforms per frame. Automatic mesh level of detail switches only at 250 and 500 studs ([Roblox docs](https://create.roblox.com/docs/reference/engine/enums/RenderFidelity)), beyond the fog, so author low-poly fish and swap in pooled lower-detail meshes yourself.

Every fish part should be anchored with collision, touch, query and shadow casting off, and all rigid fish moved by one preallocated `workspace:BulkMoveTo` call per frame. In the same 1,000-assembly test on PC, CFrame or BulkMoveTo moves cost ~6 ms of script time plus ~3 ms of engine bookkeeping. Writing `Motor6D.Transform` on parts jointed to Terrain cut script time to ~1 ms, which is worth benchmarking on a phone. Fish get no Humanoids or Animators: nearby fish sway procedurally, mid-range fish update at 30 Hz or less, and fog-edge fish update at 10–15 Hz or render as merged school impostors. ABZÛ reportedly went from ~100 to ~10,000 on-screen fish by replacing skeletal animation with math ([Kill Screen](https://killscreen.com/abzu-2)). Skip EditableMesh for crowds and oceans; it is limited to ID-verified 13+ creators and runs on strict client memory budgets ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/EditableMesh)). Every movement cost above was measured on PC, and no mobile figures exist.

### Soft lighting and fake water replace Future, Bloom and Terrain water

SMASH's **Future lighting plus Bloom** should go. Under Unified Lighting, Future maps to `LightingStyle = Realistic` with `PrioritizeLightingQuality` enabled, which deliberately lowers draw distance on weak devices to protect lighting quality ([DevForum](https://devforum.roblox.com/t/let-there-be-unified-light-unified-lighting-is-fully-live/3401512)). Shadows vanish entirely below quality level 4 ([Roblox docs](https://create.roblox.com/docs/performance-optimization/improve)). An underwater scene is dominated by fog and ambient color, and Roblox publishes no mobile cost for Atmosphere, Bloom or color grading ([Roblox docs](https://create.roblox.com/docs/environment/post-processing-effects)). So compare Soft against Realistic with prioritization disabled on the baseline phone, keep Bloom subtle or off, drop depth of field and sun rays, and build bioluminescence from Neon materials rather than many PointLights.

Avoid a Terrain water volume. A 2024 report that it renders incorrectly with StreamingEnabled was still open in early 2026 ([DevForum](https://devforum.roblox.com/t/terrain-water-renders-wrong-with-streamingenabled/3068489)), and developers note the water system has barely changed in five years ([DevForum](https://devforum.roblox.com/t/more-features-to-the-terrain-water-system/4822004)). Fake the ocean instead with four pieces: Atmosphere and fog driven by the camera's depth zone, a color-correction tint, a small dark skybox (Atmosphere does not fog the sky, [Roblox docs](https://create.roblox.com/docs/reference/engine/classes/Atmosphere)), and a camera-following surface mesh seen from below. Expanded Terrain reached full launch on October 22, 2026, with a benchmarked 90% cut in CPU memory. As of October 27, though, its client-side performance gains were switched off pending a crash fix, and terrain thinner than 16 voxels can vanish under small streaming radii ([DevForum](https://devforum.roblox.com/t/full-launch-publish-games-with-custom-terrain-materials-and-performance-improvements/4950620)). It is usable for a thick seabed, but not yet a performance win.

Texture streaming has covered all platforms since March 2026 and cut one template's texture memory from 280 MB to 155 MB. It skips Terrain, Sky, UI and the Water material ([DevForum](https://devforum.roblox.com/t/introducing-texture-streaming/4144855)), and texture memory scales with pixel count: a 1024² image costs four times a 512² one ([Roblox docs](https://create.roblox.com/docs/projects/performance-optimization/memory)). The rules still apply: 256² fish textures, 512² or smaller for hero sharks, and tinting instead of separate color variants. Some fighting-game staples also fail to transfer. Clients render at most 255 Highlights, and disabled ones still hold slots ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/Highlight)), so reserve them for one or two temporary targets and pool nameplates for the nearest few players.

### Android-only native code and an 800 MB ceiling set the CPU and memory plan

Native code generation for LocalScripts has shipped **on Android only** ([Roadmap](https://devforum.roblox.com/t/creator-roadmap-2026-fall-update/4880208), [DevForum](https://devforum.roblox.com/t/enable-native-for-clients/3170510?page=3)). No other client platform is listed, so assume iPhones interpret client Luau, size fish counts for the interpreter, and treat `--!native` on hot client modules as an Android bonus. Use `PreRender`, which blocks rendering until it returns, only for the camera ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/RunService)). Spread distant-fish updates across frames, avoid per-fish allocations, and budget roughly 2–4 ms of client Luau per frame for fish, effects and UI.

A working target of ~500–600 MB total client memory on 2–3 GB phones leaves headroom under the ~800 MB ceiling. Validate only on hardware. The on-device MicroProfiler serves captures to a desktop browser on port 1338 ([Roblox docs](https://create.roblox.com/docs/performance-optimization/microprofiler)). The Creator Hub dashboard charts memory-usage percentage by device type, and out-of-memory exits ([Roblox docs](https://create.roblox.com/docs/production/analytics/performance)). Roblox warns that Studio's emulator is inaccurate for memory ([Roblox docs](https://create.roblox.com/docs/performance-optimization/design)).

## ProfileStore and Animation Graphs replace Lyra and crunchyroll

Lyra's strengths — atomic multi-player transactions, automatic sharding, validation and built-in migrations ([GitHub](https://github.com/paradoxum-games/lyra)) — solve problems this game does not have. A profile of currency, unlocked sharks, upgrades and settings is a few kilobytes against a 4 MB per-key limit, and there is no trading. Meanwhile, Lyra has shipped nothing since 0.6.0 on July 8, 2025, and its README still says "early development." Its orphan-file and buffer fixes exist only on the unreleased main branch, and nothing upstream addresses lock refresh ([GitHub](https://github.com/paradoxum-games/lyra/releases), [GitHub](https://github.com/paradoxum-games/lyra/pulls?q=is%3Apr)). Staying would mean maintaining a fork of the data layer.

**ProfileStore 1.0.3** is the lower-risk default. Its session locking asks the server holding a profile for a final save before handing it over, which suits flaky mobile rejoins. It adds `Reconcile`, a mock store and explicit support for securing developer-product purchases, and its one open issue is a question ([API docs](https://madstudioroblox.github.io/ProfileStore/api/), [GitHub](https://github.com/MadStudioRoblox/ProfileStore/issues)). A fresh universe needs no migration from Lyra. Store a schema version and run ordered migration steps before `Reconcile`, which only adds missing keys.

Leaderboards are the scarce resource. Each server gets only 30 + 5 × players ordered writes per minute, against 60 + 40 × players standard writes ([Roblox docs](https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits)). Write all-time stats at session end, cache top-N reads for a minute, and use a MemoryStore sorted map for a live "biggest sharks" board. Storage stopped being a concern when Roblox raised it on July 29, 2026 to 500 MB plus 1 MB per lifetime player ([DevForum](https://devforum.roblox.com/t/unifying-data-stores-open-cloud-and-game-apis-and-increasing-storage-limits/4739240)).

The same profile anchors purchases. Roblox keeps no per-user purchase history. It retries `ProcessReceipt` on rejoin when the handler returns `NotProcessedYet`, and it warns against granting items from `PromptProductPurchaseFinished` ([Roblox docs](https://create.roblox.com/docs/production/monetization/developer-products)). The idempotent pattern checks a bounded ring buffer of recent `PurchaseId`s in the profile, applies the grant and records the id in one synchronous mutation, and returns `PurchaseGranted` only after `Profile:Save()` succeeds. A newer `BindReceiptHandler` API exists, but the docs do not say whether it supersedes `ProcessReceipt` ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/MarketplaceService#ProcessReceipt)). Display prices from `GetProductInfoAsync`, because managed regional pricing and the Roblox-funded discount for Roblox Plus members change them per user. Roblox Plus launched April 30, 2026, and it also pays creators 250 Robux a month for each new subscriber's first three months when sign-ups come through `PromptRobloxSubscriptionPurchase` ([DevForum](https://devforum.roblox.com/t/introducing-roblox-plus/4567894/1)). Analytics allows 120 + 20 × CCU requests per minute and 100 custom event names ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/AnalyticsService), [Roblox docs](https://create.roblox.com/docs/production/analytics/custom-events)), so log eating per life, never per fish.

**vide** is the only declarative UI library with 2026 releases: 0.4.1 on July 11, plus strict-mode and priority-order fixes merged in late October ([GitHub](https://github.com/centau/vide/releases), [GitHub](https://github.com/centau/vide/commits/main)). React-lua has been silent since December 2024, and Fusion's last release was August 2024 ([GitHub](https://github.com/jsdotlua/react-lua/releases), [GitHub](https://github.com/dphfox/Fusion/releases)). Upgrade to 0.4.1, migrate to `create(class)(props)`, and use vide for menus, the shop and shark selection. Write per-frame HUD values such as the growth bar and boost meter directly, at 10–15 Hz.

Mobile layout rules are concrete. Keep HUDs inside `ScreenInsets = CoreUISafeInsets` and avoid the legacy FullscreenExtension ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/ScreenGui.md)). Make touch targets at least 9 × 9 mm ([Roblox docs](https://create.roblox.com/docs/tutorials/curriculums/user-interface-design/choose-an-art-style)), which is about 56 px at Roblox's ~160 dpi normalization, where TextSize 20 is roughly an eighth of an inch tall ([DevForum](https://devforum.roblox.com/t/specific-details-about-ui-scaling-best-practices/3888004)). Keep CanvasGroup off large panels, because it renders blank once a device's memory cap is exceeded ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/CanvasGroup.md)).

TopbarPlus 3.5.0 (October 19–20, 2026) matches the current Core UI and spaces icons around the health bar ([GitHub](https://github.com/1ForeverHD/TopbarPlus/releases)). Charm 0.11.1 with charm-sync 0.4.1 is an optional, actively maintained way to sync profile state to clients as small patches ([GitHub](https://github.com/littensy/charm/releases)). Small utilities should come from LemonSignal 2.0.0, Trove and `t` 3.1.1 rather than the red-blox modules archived in March 2025 ([GitHub](https://github.com/red-blox/Util)).

crunchyroll solves a problem this game does not have. It computes Motor6D rig poses without an Animator, and its examples are R6 rigs. It says nothing about bones or skinned meshes, and it has been inactive since December 13, 2025 with fixes unreleased ([GitHub](https://github.com/ffrostfall/crunchyroll), [CHANGELOG](https://raw.githubusercontent.com/ffrostfall/crunchyroll/main/CHANGELOG.md)). Its one unique benefit, solving poses on the server for hitboxes, is moot when a bite hitbox is a sphere on the jaw.

Each player shark should be a single skinned MeshPart with a few spine, tail, jaw and fin bones, under an AnimationController and Animator ([Roblox docs](https://create.roblox.com/docs/reference/engine/classes/AnimationController)). Drive it with one **Animation Graph**, generally available since July 2026, that blends idle, cruise and dash on a speed parameter and layers bite and boost states. In Automatic mode, player graphs run on the owning client and replicate their parameters, which keeps animation responsive on bad networks ([Roblox docs](https://create.roblox.com/docs/animation/graph-editor)). The graph docs do not confirm support for AnimationController- or bone-driven rigs, so prototype that first, and watch the Animation category of the new Client CPU Time chart ([DevForum](https://devforum.roblox.com/t/weekly-recap-july-13-%E2%80%93-17-animation-graphs-go-live-5%C3%97-more-data-store-storage/4743286)).

### "Shark Evolution" should stay a codename

Roblox's guidelines state that copyright "does not protect facts or ideas," so eat-to-grow, real shark species, boosts, health drain and PvP biting are fair game. Trademarks and specific expression are protected, though. Valid notices remove content quickly, and repeat infringers can lose their accounts ([Roblox docs](https://create.roblox.com/docs/production/publishing/ip-guidelines)). "Hungry Shark" is a trademark: the 2013 acquisition filing names it as one ([AMF filing](https://echanges.dila.gouv.fr/OPENDATA/AMF/CNS/2013/10/FCCNS120680_20131001.pdf)), and current store listings carry the ® mark ([Nintendo eShop](https://ec.nintendo.com/apps/0100E1A00AF40000/US)). Ubisoft still supports Hungry Shark Evolution and Hungry Shark World ([Wikipedia](https://en.wikipedia.org/wiki/Hungry_Shark)), and rights holders can request removal of whole games through Rights Manager ([Roblox docs](https://create.roblox.com/docs/production/publishing/rights-manager)). Publish under a distinct title, avoid echoing the franchise's logo, HUD, shark-select screens and fantasy sharks, and keep a record of where each asset came from. This is a reading of Roblox's stated policy, not legal advice, and no trademark registry was checked.

## SMASH's toolchain needs patches, not a rebuild

Rokit is the community-standard toolchain manager. Rojo's release notes list it as the first install route, it reads `aftman.toml` and `foreman.toml` natively, and 1.2.0 (September 30, 2025) is current ([GitHub](https://github.com/rojo-rbx/rokit), [Rojo v7.7.1](https://github.com/rojo-rbx/rojo/releases/tag/v7.7.1)). Aftman's repository is archived, with its last release in May 2024 ([GitHub](https://github.com/LPGhatguy/aftman)). SMASH's project-local Aftman fallback therefore only adds problems: a second Rojo pin that can drift, a competing shim directory on PATH, and a silent failure mode, since Rokit ignores a compatibility manifest it cannot parse ([GitHub](https://github.com/rojo-rbx/rokit/issues/93)). Delete it.

**Rojo 7.7.1** (October 2, 2026) fixes "a myriad of problems" with Windows `\\?\` path prefixes, which matters directly on the developer's Windows machine. Because 7.7.0 moved live sync to WebSockets and MessagePack, upgrade the Studio plugin together with the CLI ([Rojo v7.7.0](https://github.com/rojo-rbx/rojo/releases/tag/v7.7.0)). Watch issue #1300, in which `rojo serve` on 7.7.0 stops noticing new files ([GitHub](https://github.com/rojo-rbx/rojo/issues/1300)). Roblox's native Script Sync reached full release on June 17, 2026, but it syncs only scripts and folders, treats Studio as the source of truth and emits no sourcemap ([Roblox docs](https://create.roblox.com/docs/scripting/sync)). It cannot replace `rojo build`, Wally package mounts or luau-lsp integration, and it should never share instance trees with Rojo.

**Wally 0.3.2** stays. jecs, ProfileStore, Charm, Planck and Roblox's own Jest packages all publish there. The 0.4.0 alphas change the lockfile format, and they added and then removed a `--locked` flag within a month ([GitHub](https://github.com/UpliftGames/wally/releases/tag/v0.4.0-alpha.1)). pesde is active at 0.7.4, but it offers jecs only through a third-party mirror ([pesde index](https://github.com/pesde-pkg/index/blob/main/marked/jecs)).

Testing gains a layer rather than changing direction. Upgrade **Lune to 0.11.1** (October 21, 2026) for an HTTPS-certificate security fix ([GitHub](https://github.com/lune-org/lune/releases/tag/v0.11.1)). More importantly, 0.11.0 corrected `CFrame.lookAt`, `lookAlong` and `CFrame.new(pos, lookAt)`, which returned wrong rotations whenever rotation was not purely about the Y axis ([GitHub](https://github.com/lune-org/lune/releases/tag/v0.11.0)). That bug was harmless for yaw-only fighters but breaks headless tests of a shark that pitches and rolls. Keep the Lune harness for fast logic tests rather than porting it to Lute, Roblox's official runtime, which reached 1.0 in April 2026 but documents no equivalent of Lune's Roblox instance library ([GitHub](https://github.com/luau-lang/lute/releases/tag/v1.0.0)).

Add **Jest Roblox 3.20.1**, Roblox's official Jest port. It has been on Wally since July 30, 2026, replaces the archived TestEZ ([CHANGELOG](https://github.com/Roblox/jest-roblox/blob/master/CHANGELOG.md), [GitHub](https://github.com/Roblox/testez)), and runs inside the real engine through the Open Cloud Luau Execution API. That API runs no physics and starts no scripts automatically, can touch real DataStores, allows five task creations per minute and ten unfinished tasks per place, and times out after five minutes by default ([Roblox docs](https://create.roblox.com/docs/cloud/reference/features/luau-execution)). Batch every spec into one task, run against a place in a separate test universe.

For play-mode and client-server tests, **rodeo 1.5.1** (October 27, 2026) drives Studio locally ([GitHub](https://github.com/rodeo-rbx/rodeo/releases/tag/v1.5.1)). Its 1.5 line is the first stable release since 1.3.0. Its CLI, server and plugin must be the same build, the repository moved to the rodeo-rbx organization, and Linux is unsupported, so these tests cannot run on stock Linux CI runners ([GitHub](https://github.com/rodeo-rbx/rodeo/releases/tag/v1.5.0), [GitHub](https://github.com/rodeo-rbx/rodeo)). Studio's Server & Clients mode simulates at most eight clients ([Roblox docs](https://create.roblox.com/docs/studio/testing-modes)), so 20-player load needs live test servers.

Pin luau-lsp 1.70.1, StyLua 2.6.0 and Selene 0.32.0, and upgrade them together, since new Luau syntax breaks older parsers ([GitHub](https://github.com/JohnnyMorganz/luau-lsp/releases/tag/1.70.1), [GitHub](https://github.com/JohnnyMorganz/StyLua/releases/tag/v2.6.0), [GitHub](https://github.com/Kampfkarren/selene/releases/tag/0.32.0)). Strict Luau stays, but the choice of type solver is now a live decision. The new type solver became the default only for nonstrict and nocheck scripts in November 2025. Strict projects stay on the old solver unless they opt in, and the old solver is guaranteed only "through 2026" ([DevForum](https://devforum.roblox.com/t/general-release-luau%E2%80%99s-new-type-solver/4084991)). Trial the new solver from day one in Studio, in luau-lsp (where it is still flagged "preview," [GitHub](https://github.com/JohnnyMorganz/luau-lsp/blob/main/editors/code/package.json)) and in CI. Fall back only if generic-heavy ECS types produce too many false errors.

The 2026 delivery pipeline uses official tools end to end. Every pull request runs `setup-rokit` ([GitHub](https://github.com/CompeyDev/setup-rokit)), `wally install`, sourcemap generation, luau-lsp, Selene, StyLua and the Lune specs. Merges then run `rojo build`, publish to a test place with `versionType=Saved` through the Open Cloud place-publishing API, run Jest through Luau Execution against that version, and promote to `Published` behind a gate. The publishing guide says places containing SurfaceAppearance, PartOperation or EditableMesh instances should be published from Studio after changes ([Roblox docs](https://create.roblox.com/docs/cloud/guides/usage-place-publishing)). That describes PBR shark skins and union reefs exactly, so keep art in a base place authored in Studio, or prove in the test universe that the automated publish preserves it. Use Asphalt 2.0.2 for asset uploads, since Tarmac has been stale since 2024 ([GitHub](https://github.com/jackTabsCode/asphalt/releases/tag/v2.0.2), [GitHub](https://github.com/rojo-rbx/tarmac)).

Roblox archived its standalone MCP server on April 3, 2026, in favor of one built into Studio with `execute_luau`, playtest, console and screen-capture tools ([GitHub](https://github.com/Roblox/studio-rust-mcp-server/releases/tag/END), [Roblox docs](https://create.roblox.com/docs/studio/mcp)). In a Rojo project, AI agents should edit files on disk and use MCP only to run, playtest and inspect.

Poor-network testing finally has a first-party tool. The Network Simulator, generally available since October 16, 2026, includes a "Bad Connection (3G)" preset: 150 ms latency with 70 ms jitter inbound, and 180 ms with 90 ms jitter outbound ([DevForum](https://devforum.roblox.com/t/4861695), [Roblox docs](https://create.roblox.com/docs/studio/network-simulator)). It caps packet loss at 0.5% and has no bandwidth limit, however. Realistic loss and thin downlinks still require real phones on cellular for 10–15-minute sessions, as Roblox's hardware-testing guide recommends ([Roblox docs](https://create.roblox.com/docs/performance-optimization/test-on-hardware)).

## Conclusion

SMASH's real lesson is about where to spend precision. A fighting game needs authoritative precision everywhere, because any frame of any fighter can decide a hit. A grow-and-evolve game needs authority over one question — who ate what, and when — and a ring buffer plus a clamped rewind answers it after the fact. Closed-form schools are the hinge of the design because one artifact solves three problems: the same seeded path function cuts bandwidth to one record per school, removes interpolation delay for most prey, and makes bite validation exact rather than approximate. Every expensive mechanism SMASH built answers a question this game never asks.

The practical implication is the order of work. The riskiest assumptions in this plan are cheap to test now and expensive to discover late: movement costs measured only on PC, community bandwidth figures, an Animation Graph on a bone rig, SwimController outside water, and the rewind caps. The first milestone, before any content production, should be a vertical slice of 300 fish and 20 sharks on a 2–3 GB Android phone and an older iPhone, over a real cellular link, judged against the p95 frame targets and the ~600 MB memory line. Four decisions then get explicit triggers for re-evaluation. Adopt Server Authority only after the high-ping input-delay bug is verifiably fixed and a multi-device test at 150–300 ms passes. Move to Blink 1.0 once it ships quantized types and the oversized-buffer guard, take Wally 0.4 when it reaches a stable release, and rely on SLIM once Roblox confirms it on mobile and extends it to NPCs, which its roadmap schedules for early 2027 ([Roadmap](https://devforum.roblox.com/t/creator-roadmap-2026-fall-update/4880208)).
